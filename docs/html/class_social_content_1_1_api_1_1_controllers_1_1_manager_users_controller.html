CancellationToken ct )
inline

Zanonimizuj managera (skasowanie danych osobowych).

Przeznaczone dla próśb o skasowanie danych. Zamienia imię i nazwisko na "Usunięty użytkownik", zastępuje opis informacją o usunięciu danych i usuwa konto logowania (e-mail i hasło), co natychmiast unieważnia wydane tokeny.

Powiązania z postami oraz z kontami społecznościowymi pozostają nienaruszone, więc historia publikacji jest zachowana. Wiek nie jest zmieniany. Operacji nie można cofnąć. Można ją wykonać na każdym managerze firmy, także bez powiązań i bez konta logowania.

Parametry
idIdentyfikator managera (GUID).

<response code="200">Manager po anonimizacji.</response> <response code="401">Brak tokenu, token nieprawidłowy lub wygasły albo dostęp konta został zablokowany.</response> <response code="403">Zalogowany użytkownik nie ma roli CompanyUser.</response> <response code="404">Manager o podanym identyfikatorze nie istnieje w tej firmie.</response>

Utwórz managera w swojej firmie.

Tworzy managera (imię, nazwisko, wiek, opis) przypisanego do firmy zalogowanego CompanyUser. Email i password są wymagane: każdy nowy manager dostaje konto logowania i może tworzyć posty na przypisanych kontach.

Wymagane pola: firstName i lastName (1-50 znaków; litery, myślnik, apostrof), age (18-100), description (1-2000 znaków). Adres e-mail musi być unikalny we wszystkich rolach, a hasło ma mieć 8-128 znaków, w tym małą literę, wielką literę i cyfrę.

<response code="201">Manager został utworzony; w nagłówku Location adres nowego zasobu.</response> <response code="400">Dane nie spełniają reguł walidacji (w tym brak lub niepoprawny e-mail albo hasło).</response> <response code="401">Brak tokenu, token nieprawidłowy lub wygasły albo dostęp konta został zablokowany.</response> <response code="403">Zalogowany użytkownik nie ma roli CompanyUser.</response> <response code="409">Konto z tym adresem e-mail już istnieje.</response>

CancellationToken ct )
inline

Usuń managera (tylko bez powiązań).

Trwale usuwa managera wraz z jego danymi logowania (jeśli istnieją). Dozwolone wyłącznie wtedy, gdy manager nie ma powiązanych postów ani kont społecznościowych. Operacji nie można cofnąć.

Jeśli powiązania istnieją, zwracany jest 409 Conflict - historia publikacji musi zostać zachowana. Zamiast usuwać, zablokuj dostęp (PUT /api/ManagerUsers/{id}/access) albo zanonimizuj dane (POST /api/ManagerUsers/{id}/anonymize).

Parametry
idIdentyfikator managera (GUID).

<response code="204">Manager został usunięty.</response> <response code="401">Brak tokenu, token nieprawidłowy lub wygasły albo dostęp konta został zablokowany.</response> <response code="403">Zalogowany użytkownik nie ma roli CompanyUser.</response> <response code="404">Manager o podanym identyfikatorze nie istnieje w tej firmie.</response> <response code="409">Manager ma powiązane posty lub konta społecznościowe - zablokuj dostęp zamiast usuwać.</response>

Pobierz listę managerów firmy.

Zwraca wszystkich managerów zalogowanej firmy posortowanych alfabetycznie (nazwisko, potem imię). Wymaga tokenu JWT z rolą CompanyUser.

Odpowiedź nie zawiera adresów e-mail ani danych logowania. Pole socialAccountIds wskazuje konta społecznościowe przypisane managerowi, a hasLoginAccount i isAccessBlocked mówią, czy manager ma konto logowania i czy jego dostęp jest zablokowany.

<response code="200">Lista managerów; pusta tablica, gdy nikogo jeszcze nie dodano.</response> <response code="401">Brak tokenu, token nieprawidłowy lub wygasły albo dostęp konta został zablokowany.</response> <response code="403">Zalogowany użytkownik nie ma roli CompanyUser.</response>

Zablokuj lub odblokuj dostęp managera.

Ustawia blokadę logowania managera (blocked = true) albo ją zdejmuje (blocked = false). Zablokowany manager zostaje w systemie wraz z powiązaniami z postami, ale nie może się zalogować, a jego wcześniej wydany token przestaje działać od razu.

Dotyczy tylko managerów mających konto logowania.

Parametry
idIdentyfikator managera (GUID).
dtoPole blocked: true = zablokuj, false = odblokuj.

<response code="200">Manager po zmianie; pole isAccessBlocked odzwierciedla nowy stan.</response> <response code="400">Brak pola blocked albo manager nie ma konta logowania.</response> <response code="401">Brak tokenu, token nieprawidłowy lub wygasły albo dostęp konta został zablokowany.</response> <response code="403">Zalogowany użytkownik nie ma roli CompanyUser.</response> <response code="404">Manager o podanym identyfikatorze nie istnieje w tej firmie.</response>

Zmień e-mail i hasło managera.

Ustawia nowy adres e-mail (wymagany; unikalny we wszystkich rolach) i opcjonalnie nowe hasło (8-128 znaków, mała i wielka litera, cyfra). Pominięte password zostawia dotychczasowe hasło. Walidacja jest ta sama co przy tworzeniu managera (klasa Validate).

Manager bez konta logowania (np. zanonimizowany) dostaje je dopiero po podaniu hasła.

Parametry
idIdentyfikator managera (GUID).
dtoNowy e-mail i opcjonalnie nowe hasło.

<response code="200">Manager po zmianie.</response> <response code="400">Niepoprawny e-mail lub hasło.</response> <response code="401">Brak tokenu, token nieprawidłowy lub wygasły albo dostęp konta został zablokowany.</response> <response code="403">Zalogowany użytkownik nie ma roli CompanyUser.</response> <response code="404">Manager nie istnieje w tej firmie.</response> <response code="409">Konto z tym adresem e-mail już istnieje.</response>
